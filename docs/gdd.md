## 1. コンセプト

**「壁に弾を反射させて敵戦車を撃ち抜く、一撃必殺のトップダウン戦車パズルアクション」**

- Wii Play「タンク！」の**メカニクス（ルール）のみ**を仕様として再現する。画像・音源・コード・固有名称は一切流用せず、すべてオリジナル資産で構成する（詳細は §10 知財ポリシー）。
- プラットフォーム：PCブラウザ（デスクトップ優先）。
- プレイ形式：シングルプレイのミッション攻略が軸。ローカル2P協力は**MVP後の拡張**（§12）。
- MVP規模：**5ミッション・敵AI 2種**。

## 2. コアループ（遊びの基本サイクル）

1. ミッション開始：盤面に自機と敵戦車が配置される。
2. 移動と照準を独立に操り、直接射撃または**跳弾**（壁で反射する弾）で敵を撃破する。
3. 敵を全滅させるとミッションクリア → 次のミッションへ。
4. 被弾すると即ミス（一撃死）。残機を1つ失い同ミッションをやり直す。残機が尽きたらゲームオーバー。

**面白さの核**：①一撃死の緊張感、②「反射させれば物陰の敵に当たる」という発見、③自分の弾も自分に当たる（跳ね返りの自爆リスク）ことによる撃ちすぎ抑制。

## 3. 操作仕様

| 入力 | 動作 |
|---|---|
| W / A / S / D | 戦車の移動（8方向。車体は移動方向へ滑らかに向きを変える） |
| マウス移動 | 砲塔（砲台の回転部分）の照準。カーソル位置へ常時追従 |
| 左クリック | 射撃（押しっぱなしで連射はしない。1クリック1発） |
| スペース または 右クリック | 地雷の設置 |
| Esc / P | ポーズ（一時停止） |

- 移動と照準は完全に独立（移動しながら別方向を撃てる）。これが本作の操作の核。
- 8方向移動の斜め入力は速度を正規化する（斜め移動が速くならないようにする）。

## 3.5 タッチ操作（v0.11・Phase 7）

スマートフォン・タブレットのブラウザでも遊べるようにする。**タッチ入力を初めて検知した時点で**画面内に仮想コントロールを表示する（PCでは一切表示せず、従来の操作は不変）。

| 領域 | 操作 |
|---|---|
| 画面の左半分 | 指を置いた位置を基点とする**仮想スティック**（画面上の疑似スティック）。指をずらした方向へ移動。基点から 12px 未満は不感帯、64px で最大 |
| 画面の右半分 | 触れた位置へ砲塔が向き、**触れている間は連射**（タップ連打は指が疲れるため、マウスの「1クリック1発」とは意図的に変える） |
| 右下の地雷ボタン | タップで地雷設置（1タップ1個） |
| 右上のポーズボタン | タップでポーズ切替 |

- マルチタッチ対応：移動と照準・射撃を同時に行える（同時3点まで）。
- 仮想コントロールは半透明のコード描画（外部画像なし）。2P協力・エディタはタッチ非対応（PC専用機能として据え置き）。
- 盤面は横長（25×17タイル）なので縦持ちでは余白ができる。v0.17 は「横向きにすると大きく表示されます」と
  案内するだけだったが、v0.23 で**縦持ち専用レイアウト**（§3.6）を用意し、案内は撤去した。
- タイトルの操作説明は**入力環境に合わせて出し分ける**（v0.17）：タッチ環境ではタッチ操作だけ、
  それ以外ではキーボード・パッドの説明だけを見せる。全環境ぶんを常に並べると初見の情報量が過大になるため。

## 3.6 縦持ちレイアウト（v0.23・§14 の E2）

盤面は横長（25×17）なので、スマホの**縦持ちでは画面の上下に大きな余白**ができ、
さらに仮想コントロールが盤面に重なって見づらかった。v0.11〜v0.22 は「横向き推奨」の案内だけで済ませていた。

**縦持ちのときだけ canvas を下へ伸ばし、伸ばした帯にコントロールを追い出す。**

- 帯の高さは**画面の縦横比にぴったり合わせる**。表示は縦横比を保って画面に収める（FIT）ので、
  canvas の比が画面と違えばその差はそのまま黒い余白になる。帯を画面の比まで伸ばせば
  **余白だったところがそのまま操作面積に変わる**（盤面の表示サイズは変わらない＝小さくならない）。
  極端な比の端末でも破綻しないよう上下限（240〜1400px）で挟む。
- **盤面は 800×544 のまま**。レベルデザインも当たり判定も座標系も一切変えない。
  帯に置くのは仮想スティック・地雷ボタン・ポーズボタンだけ。
- 判定は起動時に一度だけ、**タッチ環境かつ縦持ちのとき**のみ。
  途中で回転しても作り直さない（canvas を作り直すことになるため）。
- メニュー系の画面（タイトル・ミッション選択・実績・エディタ）は帯を使わないので、
  カメラを盤面の中心に寄せて画面の中央に置く（そうしないと文字が上寄りになり下が丸ごと空く）。
- 「横向きにしてください」の案内は**撤去**した。専用レイアウトができて不要になったうえ、
  画面に固定表示すると盤面や操作帯に重なるという実害があった。
- 寸法計算は純粋関数（`core/portraitLayout.ts`）に置き、
  「canvas の比が画面の比と一致する＝余白が出ない」ことを単体テストで機械検証する。

**未対応（今後の候補）**：帯に触れて照準するとき、狙いは「触れた点の方向」で決まる。
盤面から遠い位置ほど角度の刻みが粗くなるので、帯の中では相対的な照準に切り替えるほうが精密に狙える。

## 5. 弾の物理仕様

- 弾は直進し、**壁に当たると入射角＝反射角で反射**する（跳弾）。反射回数が上限を超えたら消滅。
- **弾同士は相殺する**：弾と弾が接触すると両方消滅する（敵弾を撃ち落とせる。原作の重要メカニクスのひとつ）。
- 弾は発射者を問わず全戦車に当たる（自分の跳ね返り弾で自爆あり）。
- 破壊可能壁（§7）に当たった弾は反射せず、壁を破壊はしない（MVPでは壁破壊は地雷の爆風のみ）。

### 弾の見た目（v0.16・見た目のみの仕様）

弾は**ミサイル型**で描く（オリジナルデザイン。§9 のブロック調に合わせた図形の組み合わせ）。
**当たり判定は従来どおり中心 (x,y)・半径 4px の円のまま**で、見た目の変更が挙動に影響してはならない。

- 向きは**進行方向**（速度ベクトル）に一致させる。跳弾すると向きも変わる。
- **弾頭の先端を当たり判定の円の縁に合わせる**。胴体・尾翼・噴射炎は後方へ伸ばす
  （前方にはみ出させない＝「当たったように見えるのに当たらない」を作らない）。
- 榴弾（敵M「ボマー」）は暖色（`COLORS.SHELL`）で描き、通常弾と区別できるようにする（§6 の意図どおり）。
- 噴射炎は弾ごとに位相をずらして明滅させる（全弾が同時に点滅しないようにする）。

**弾の種別ごとの見た目（v0.20）** — 「どの敵の弾か」を一目で見分けられるようにする。
種別は弾自身が `style` として持ち、**挙動の数値（反射上限・信管の有無）から推測しない**
（数値を調整しただけで絵が変わってしまうため）。

| 種別 | 見た目 | 意図 |
|---|---|---|
| 通常弾 | ミサイル型（弾頭＋胴体＋尾翼＋噴射炎） | 既定 |
| 敵C「スナイパー」弾 | **細長い徹甲弾＋後方へ伸びる曳光** | 340px/s と最速。「速くて細い」ことを形で伝える |
| 敵G「プリズム」弾 | **自転する結晶＋残り反射回数ぶんの輪** | 3回反射して長く飛び回る。あと何回跳ねるかを輪の数で読ませる |
| 敵M「ボマー」の榴弾 | 暖色のミサイル | 反射せず炸裂する弾であることを色で区別 |

いずれも**当たり判定は不変**（中心・半径4pxの円）。スナイパー弾は弾頭の先端を判定の縁に合わせ、
プリズム弾は結晶の実体を判定と同じ大きさにする（輪だけを外側に薄く描く）。

## 5.2 自滅・同士討ちの禁止（v0.12・Phase 8）

**敵は敵の攻撃では破壊されない。** プレイヤーが関与しない限りミッションは進行しない、という原則を実装で保証する。

| 攻撃元 | プレイヤー戦車への効果 | 敵戦車への効果 |
|---|---|---|
| プレイヤーの弾 | 当たる（自分の跳ね返り弾での自爆＝仕様どおり維持） | 当たる |
| 敵の弾 | 当たる | **当たらない**（自弾自爆・同士討ちとも発生しない） |
| プレイヤーが設置した地雷の爆風 | 当たる | 当たる |
| 敵が設置した地雷の爆風（時限起爆・敵の接近） | 当たる | **当たらない** |
| 敵が設置した地雷の爆風（**プレイヤーが誘爆させた場合**） | 当たる | **当たる** |

- 「プレイヤーが誘爆させた」＝プレイヤーの弾が触れた／プレイヤーが接近した／プレイヤー起因の爆発から連鎖した、のいずれか。連鎖の起点がプレイヤーなら連鎖先も同様に扱う。
- これにより「敵の地雷を撃って敵を巻き込む」戦術は維持しつつ、無操作での自壊クリアを構造的に防ぐ。
- 背景：QAの無操作計測で M3 が30回中10回（最短5.2秒）自壊クリアしていた。

## 5.3 砲口位置の壁補正（v0.12・Phase 8）

弾は発射者中心から砲口オフセット（22px）の位置に生成するが、**その位置が壁の内部になる場合は、壁に入らない最も遠い位置まで手前に寄せる**。壁際で撃ったときに弾が壁内に湧き、押し戻しで即座に自機へ命中する（＝理不尽な即死）／壁をすり抜ける／横に瞬間移動する、という不具合を防ぐ。

## 5.5 戦車の衝突仕様（v0.2 追加・オーナー承認済み）

- 戦車同士は通り抜けできない（互いに通行不可の障害物として扱う。重なり防止）。
- 戦車は壁タイル（`#`・`X`）と穴（`H`）に進入できない。

## 6. 敵AI仕様（MVP：2種）

> 敵の名称はオリジナル。ステートマシン（状態機械＝「待機・照準・射撃」などの状態遷移で行動を管理する設計）で実装する。

### 敵A「セントリー」（固定砲台型）
| 項目 | 値 |
|---|---|
| 移動 | しない（その場で砲塔だけ回す） |
| 照準 | プレイヤーへ追従（回転速度 115°/s。v0.4で 90→115 に強化）。ときどきランダムにブレる（±2°） |
| 弾速 / 反射上限 | 225 px/s / 1回（v0.4：敵弾のみ 200→225 に強化。プレイヤー弾は200のまま） |
| 同時発射数上限 | 1発 |

### 敵F「チェイサー」（追跡型・v0.9 追加／v0.24 強化）
| 項目 | 値 |
|---|---|
| 移動 | **130 px/s**。プレイヤーを追跡するが、**間合いを取る**：プレイヤーから 3〜6 タイル離れた床タイルを目標に選び直し続ける（引き直し間隔 1.0〜2.0 s） |
| 照準 | 回転速度 200°/s |
| 弾 | 弾速 225 px/s（難易度倍率対象）・反射1回・**同時2発** |
| 発射間隔 | 平均 **0.85 s**（±0.3 s） |
| 回避 | ローバーと同方式（成功率50%固定） |
| 耐久 / 識別 | 1 / 白銀系のオリジナル配色 |

> **v0.24 の強化理由**：以前は「プレイヤーの±3タイル以内」を目標にしていたため、**至近距離まで詰めてきて
> そのまま撃たれるだけの的**になっていた（オーナー指摘「白のタンクの敵が弱すぎる」）。
> 目標を**円環（3〜6タイル）**に変え、詰めきらず周囲を回り続けるようにした。
> 弾速も反射回数も変えていない（＝対処法は変わらない）が、
> 「近づいて処理する」が通じなくなり、**動きながら撃ち合う**相手になる。

### 敵G「プリズム」（多重反射砲台型・v0.10 追加）
| 項目 | 値 |

#### 跳弾狙撃の反射点をいつ計算するか（v0.23）

反射点の探索は「外周4辺ぶんの候補それぞれについて射線を2本判定する」処理で、
固定砲台のなかで最も重い。**毎フレームではなく 0.08 秒ごとに計算し直し、間は前回の結果を使う。**
標的が 64px 以上動いたとき（＝別のプレイヤーへ切り替わったとき等）は間隔を待たずに引き直し、
跳弾狙撃をやめたら結果を捨てる。

0.08 秒は 60fps で約5フレーム。標的が 120px/s で動いても狙いのずれは約10px、
200px 先なら約3°で、発射許容角（0.15rad≒8.6°）の半分以下に収まるため撃つ／撃たないの判断は変わらない。
実測で反射点の探索回数は **300フレームあたり 300回 → 60回（80%減）**。

## 7. ステージ仕様

- 盤面：**タイルグリッド（マス目）方式**。1タイル = 32 px、盤面 = 25×17 タイル（800×544 px）＋外周は必ず壁。
- タイル種別（MVP）：
  - `.` 床 … 通行・弾通過可
  - `#` 恒久壁 … 通行不可・弾は反射
  - `X` 破壊可能壁 … 通行不可・弾は消滅（反射しない）・地雷の爆風で消滅・敵AIの射線判定でも遮蔽扱い（v0.2.1 明確化）
  - `H` 穴 … 戦車は通行不可・**弾は上を通過する**（撃ち合い専用の地形）
- ステージデータはコードから分離：Phase 1 は文字列グリッド、Phase 2 以降は JSON ファイル。

#### 地形の型（v0.24）

**v0.13〜v0.23 の生成器は「ランダムな矩形ブロックをいくつか置く」だけだった**ため、
34面が全部同じ顔になっていた（オーナー指摘「ステージが単調でステージ構成に面白みがない」）。
面ごとに**地形の型**を選び、その型に沿って地形を組み立てる方式に変える。

| 型 | 地形 | 生まれる遊び |
|---|---|---|
| 広間（open） | まばらな島。従来の形 | 撃ち合いと回り込み |
| 回廊（corridor） | 縦横の通路が格子状に走る | 曲がり角の読み合い。**地雷が効く** |
| 四部屋（rooms） | 十字の隔壁で4部屋に分け、各壁に1つずつ出入口 | 出入口の管理。**地雷が最も効く** |
| 柱林（pillars） | 1×1 の柱を多数散らす | 跳弾の宝庫。直射がほぼ通らない |
| 中央要塞（fortress） | 中央に壁で囲った小部屋、四方に入口 | 中の敵は跳弾でしか狙えない |
| 蛇行（serpentine） | 左右交互に伸びる長い隔壁 | 一本道を押し上げる圧 |
| 堀（moat） | 穴 `H` の帯で盤面を分断（弾だけ通る） | 撃ち合い専用の間合い |
| 檻（cages） | 敵を囲う小さな檻をいくつか置く | 跳弾必須の的が混ざる |

- 型は面ごとに**巡回**させる（隣り合う面が同じ型にならない）。M50 は要塞。
- 各型は必ず**通路の幅を1タイル以上**確保し、生成後の検証（到達範囲・攻撃手段・安全地帯）は従来どおり全て通す。

#### 地雷が活きる設計（v0.24）

地雷は「同時2個・接近起爆・10秒で自動起爆・X壁を壊す」という強い道具なのに、
**置く価値のある地形が無かった**（広場ばかりで敵が必ず通る場所が存在しない）。次の3点を生成条件に足す。

1. **隘路（チョークポイント）を必ず1つ以上作る** — 幅1タイルで、通らないと反対側へ行けない通路。
   回廊・四部屋・中央要塞・蛇行の型がこれを持つ。徘徊・追跡する敵は必ずここを通る。
2. **破壊可能壁 `X` を必ず2箇所以上置く** — 地雷の爆風で開通させるとルートが短縮できる位置に置く。
   従来は「50%の確率で1つ」だったので、ほとんどの面で地雷を使う理由がなかった。
3. **移動する敵を必ず1体以上入れる** — 置いた地雷を踏む相手がいなければ接近起爆は死に機能になる。



## 8.3 難易度選択（v0.9・Phase 5）

タイトル画面で EASY / NORMAL / HARD を選択できる（既定 NORMAL。選択はローカル保存し次回も維持）。難易度は敵の脅威度のみを変え、ステージ地形・敵配置は共通。

| 項目 | EASY | NORMAL | HARD |

| 敵弾速の倍率 | ×0.9 | ×1.0 | ×1.1（スナイパー弾にも適用） |
| 固定砲台の跳弾狙撃確率（A・C） | 40% | 75% | 100% |
| ローバーの回避成功率 | 35% | 50% | 65% |

- エディタのテストプレイにも選択中の難易度が適用される。

## 8.6 到達記録と「続きから」（v0.13・Phase 8）

全50ミッションを毎回 M1 からやり直すのは現実的でないため、**到達済みの最高ミッションから再開できる**ようにする。

- ミッションをクリアするたび、次のミッション番号を到達記録として保存する（localStorage。キー `hanedan.reached.<難易度>`。難易度別）。
- タイトル画面に「[3] 続きから（M<n>）」を表示する（到達記録が2以上のときのみ）。
- 「1人で出撃」は常に M1 から開始する（通し記録＝トータルタイムの対象はこちら）。続きからのランは通しトータルタイムの対象外。
- エディタのテストプレイは到達記録を更新しない。

## 8.5 演出・記録仕様（v0.7・Phase 4 第3弾）

- **撃破演出**：戦車撃破時に爆発パーティクル（コード描画の破片・閃光。外部画像なし）＋軽い画面揺れ。地雷の爆発は一回り大きい揺れ。演出時間は短く（0.3〜0.5s）、テンポを損なわない。
- **ミッションタイム**：HUD に現ミッションの経過タイムを表示（0.1秒単位）。被弾リセットでそのミッションのタイムはリセット。ポーズ・バナー中は計時しない。
- **記録のローカル保存**（localStorage＝ブラウザ内保存。サーバ送信なし）：
  - ミッション別ベストタイム（クリア時に更新判定。1P/2Pは区別しない）。
  - 全クリア時の「通しトータルタイム」ベスト（M1〜最終ミッションを通したランのタイム合計）。
  - 保存キーは `hanedan.best.*`。記録が壊れていても安全に初期化。
- **クリア演出**：ミッションクリア時にタイムと「NEW RECORD!」（ベスト更新時）を表示。全クリア画面には各ミッションのタイム一覧・合計・ベスト比較を表示。
- **タイトル画面**：トータルベストがあれば小さく表示。
- スコープ外（退避継続）：BGM、リプレイ、オンラインランキング。

## 8.7 遊び方のモード・実績（v0.23・§14 の E6）

50面をクリアしたあとに戻ってくる理由が無かったので、**盤面を増やさずに遊び方を増やす**。
新しいミッションを作るのではなく、既存50面に別のルールを与える。

| モード | 内容 | 残機 | 記録 |
|---|---|---|---|
| キャンペーン | 従来どおり M1 から順に | 難易度どおり（EASY5／NORMAL3／HARD3） | ミッション別ベスト・通しベスト・到達記録 |
| タイムアタック | 到達済みの1面を選んで遊ぶ。終わったらミッション選択へ戻る | **1**（難易度によらず固定） | そのミッションのベストタイム |
| サバイバル | 全50面を**シャッフル**して連続 | **1**（同上） | 最高クリア数（大きいほど良い） |

- タイムアタックとサバイバルの残機を難易度によらず1に固定するのは、**記録の意味が難易度で変わらないようにする**ため。
- サバイバルを「無限に自動生成し続ける」形にしないのは、面の生成器（`scripts/generateMissions.ts`）を
  ゲーム本体から import しない設計にしているため（生成物は全条件を機械検証してからミッション表に取り込む、という手順を崩さない）。
  50面のシャッフル＋残機1で「どこまで耐えられるか」の遊びとしては成立する。
- サバイバルのやり直しは**並びをシャッフルし直す**（同じ順番を覚えて攻略させない）。
- ミッション選択は**到達済みの範囲だけ**が押せる（キャンペーンで進めた意味を保つ）。
  各ミッションのベストタイムをその場に出し、「どこを詰めるか」を選ぶ画面にする。
- タイトルからの入口（タイムアタック・サバイバル）は、**到達記録がある＝一度は遊んだとき**だけ出す
  （初回起動でモードを3つ並べても選べない）。

### 実績

「まだ達成していないこと」が一覧で見えることを目的にするので、**未達成でも条件を隠さない**。

| 実績 | 条件 |
|---|---|
| 初出撃 | ミッションを1つクリアする |
| 十番勝負 / 折り返し | M10 / M25 に到達する |
| 全50制覇 | 全ミッションをクリアする |
| 無傷の帰還 | 残機を1つも失わずに全ミッションをクリアする |
| 難関突破 | HARD で全ミッションをクリアする |
| 二人三脚 | 2人プレイでミッションをクリアする |
| 早撃ち | タイムアタックで10秒以内にクリアする |
| 生存者 / 不死身 | サバイバルで10面 / 25面クリアする |

- 条件は**いま持っているデータだけで判定できるもの**に絞る。跳弾での撃破数のような新しい計測が要るものは足さない
  （計測を増やすと GameWorld に統計用の状態が増え、テストの対象が広がるため）。
- 判定は純粋関数（`evaluateAchievements`）に閉じ込め、保存は Records と同じ RecordStore 注入で行う。
- 提出はランの終了時（全クリア／ゲームオーバー）の**1か所だけ**。終了画面で「実績解除！」として告知する。
- エディタのテストプレイは記録・実績とも対象外（§12.7）。

## 8.8 チュートリアル（v0.23・§14 の E8）

跳弾は本作の面白さの核（§2）だが、初見では「壁で反射させて当てる」という発想自体が出てこない。
**教える面を3つだけ用意する**（`src/stages/tutorial.ts`）。

| 面 | 教えたいこと | 地形の要点 |
|---|---|---|
| T1「まっすぐ撃つ」 | 移動と照準が独立していること／撃てば当たること | 中央の横壁で開幕の射線は切れている。左右へ回り込めば直接狙える |
| T2「壁の裏を撃つ」 | **跳弾**。回り込めない敵に反射で当てる | 縦壁＋穴で左右に分断。左ゾーンの**どこからも直接射線が通らない**（機械検証） |
| T3「跳ね返りに気をつけろ」 | **自分の弾も自分に当たる**（撃ちすぎ抑制の動機） | 同じ行に自機と敵、間に柱1本。まっすぐ撃つと跳ね返りが自分へ戻る |

- **本編 M1〜M50 とは別立て**にする。番号を前にずらすと到達記録・ベスト記録のミッション番号が
  すべて1つずれ、既に遊んだ人の記録が壊れるため。
- 残機は 9 固定（教え切る前に終わらせない）。**記録・実績とも対象外**。
- チュートリアルのミッションだけが `hint`（画面上部に出す一言）を持つ。
  本編のミッションは持たないので、通常プレイの画面は従来どおり何も増えない（機械検証の対象）。
- タイトルからの入口は、まだ一度も遊んでいないとき（到達記録なし）は
  **「はじめての方へ」として目立つ色で**、遊んだあとは「れんしゅう」として控えめに出す。
- 盤面は本編と同じ基準で機械検証する（正規サイズ・外周は恒久壁・湧き位置は床・開幕射線なし）。
  加えて T1 は「直接狙える床が存在する」、T2 は「直接狙える床が0で、湧き位置から跳弾が成立する」ことを検査する。

## 9. アート・サウンド方針（asset-advisor 管轄）

- ビジュアル：**フラットなブロック調のオリジナルデザイン**。図形の組み合わせ（矩形＋円）でコード描画から始め、原作と配色・シルエットを明確に差別化する。
- 効果音：Web Audio API（ブラウザ内蔵の音声合成機能）で自作合成 → 不足分は CC0（著作権放棄）素材。外部素材は `assets/CREDITS.md` に出所・ライセンスを必ず記録。
- BGM（v0.11 実装）：Web Audio API による**自作合成のループ**（外部音源ファイルなし＝知財ポリシー準拠）。当初はマイナー・ペンタトニック（暗く緊張感のある5音階）だったが、v0.20.1 で **C メジャー**（明るい長音階）に変更。効果音より小さい音量で鳴らし、プレイの邪魔をしない。
  - シーン別に曲調を変える：タイトル＝軽快（テンポ 100）、ゲーム中＝軽快かつ緊迫（テンポ 144）、エディタ＝静か（テンポ 78）。
  - ミュートは効果音と共通の M キー（タッチ時は設定不要＝自動再生制限に従いユーザー操作後に開始）。BGM だけを止める B キーも用意する。
  - **M と B は別々の意思として保持し、どちらか一方でも立っていれば BGM は鳴らさない**（v0.18）。
    1つの真偽値で持つと「B で BGM を消したあと M を2回押すと BGM が復活する」＝ M の解除が
    B の指定を上書きする不具合になる。
  - **M・B はタイトル・ゲーム・エディタのどの画面でも効く**（v0.18）。どの画面でも BGM は鳴るため。
  - **曲は単調にしない**（v0.20）。8音のパターンを繰り返すだけだったのを次のように厚くする。
    **原作の旋律は使わない**（知財ポリシー）。進行・旋律ともオリジナル。
    - コード進行を持たせ、和音が小節ごとに移り変わるようにする
    - 8小節ループの前半4小節（A）と後半4小節（B）で旋律を変える
    - 層：リード（旋律。矩形波2基をずらして厚みを出しディレイを掛ける）＋パッド（和音の敷物）
      ＋ベース（ローパスで丸めた低音）＋ドラム（キック・スネア・ハイハット。テンポの速い曲のみ）
  - **曲調は明るいポップに保つ**（v0.20.1）。v0.20 の版は「マイナーキー＋マイナー7th＋鋸波＋
    深いディレイ」で不気味に聞こえたため、次の4点で作り替えた。
    - キーを **C メジャー**に統一し、王道のポップ進行を使う（タイトル C–G–Am–F＝I–V–vi–IV、
      ゲーム F–G–C–Am、エディタ C–F–C–G）。和音は長三和音・短三和音だけで **7th を積まない**
      （7th の濁りが不穏さの主因だった）
    - リードの波形を鋸波→矩形波にし、ローパスを閉じすぎない（こもると暗くなる）
    - ディレイを浅くする（深いと空間が広がりすぎて不穏になる）
    - テンポを上げ、ハイハットを8分で刻んで前へ進ませる
  - **長く聴いていられる曲にする**（v0.21）。v0.20.1 は明るくなったが、旋律が
    **1小節（8音）のパターンの繰り返し**だったため数十秒で耳に付いた。
    ゲーム音楽の定石（ループは30秒〜2分／同じ音量が続くと聴き疲れる／
    強い倍音は長時間で耳に刺さる）に沿って次の6点を直した。
    - 旋律を**4小節（32音）のフレーズ**単位で書き、**A→B→A→C の16小節形式**で並べる。
      結びのフレーズ C は主和音へ戻して終える＝ループの継ぎ目が目立たない
    - 音の長さを揃えない（伸ばす記号 HOLD を置く）。緩急が「歌っている」感じを生む
    - 強弱を付ける（拍頭は強く、それ以外は弱く。ハイハットも裏拍を弱く）
    - リードの主波形を**三角波**にする（矩形波は高次倍音が多く長時間で耳に刺さるため、
      矩形波は芯を足す副波形として小さく重ねるだけにする）
    - **アルペジオ**（和音を分散して鳴らす層）を足し、**旋律が休んでいる間だけ**鳴らす
      （コール＆レスポンス＝隙間を埋めつつ音を濁らせない）
    - **スウィング**で裏拍を少し後ろへずらし、機械的な等間隔を崩す
    - テンポはタイトル 92／ゲーム 124／エディタ 78（ループ長は順に約42／31／49秒）
  - **プレイ中は緊張感を優先する**（v0.21.1）。タイトルとエディタは明るいままにし、
    ゲーム中の曲だけを張り詰めた響きに変える（遊んでいる最中に一番効くため）。
    音階は C メジャーのままで**音階外の音は一切足さない**＝「不気味」に逆戻りしない。
    - 主役の和音を **A マイナー**（C メジャーの平行短調＝使う音は同じで中心だけが変わる）へ移す。
      進行は Am → F → G → Am。最後に Am へ戻るので**解決しきらず緊張が続く**
    - 結びのフレーズは主音 A ではなく**第5音 E** で止める（着地させない）
    - ベースは根音を刻み続ける（心拍のような一定の圧）
    - キックを3拍目の裏に食い込ませて前のめりにする（ドラムのパターンは調整値として持つ）
    - スウィングを 0 にする（スウィング＝ゆとり。等間隔のまま緊迫させる）
    - 旋律に8分1つぶんの短い音を混ぜ、同じ音を刻んで食い下がる形にする
  - **ジャンルは「軽快なジャズ／ラウンジ調」に寄せる**（v0.22）。
    **原作の旋律・和音の並び・音色を写すことは一切しない**（§10 知財ポリシー）。
    合わせるのは著作権の保護対象ではない**ジャンル・編成・リズムの作法**だけで、
    旋律はすべて自作のオリジナルである。使う技法は次の4つ。
    - **スウィング**を強める（0.22）＝跳ねるリズム。ジャンルの手触りの半分はこれで決まる
    - **ウォーキングベース**：拍ごとに根音→第3音→第5音→第7音と歩いて上がる。
      ベースの調整値は「その和音の構成音の番号」で持つので、**どの和音でも必ず構成音**になる
    - **循環進行**（ii–V–I の並び）を使う。タイトルは C6→Am7→Dm7→G7、
      ゲーム中は Am7→Dm7→G7→C6（マイナーの和音から始めて緊張を残す）
    - **短7度（Am7・G7 など）を解禁**する。v0.20 の「不気味さ」の原因は鋸波・深いディレイ・
      遅いテンポと重なったことで、短7度そのものではなかった。
      ただし**長7度（11半音）は引き続き使わない**（浮遊感が強すぎる）
    - ドラムは 2・4拍目のバックビートと軽いキックだけに留める（音数を増やさない）
    - テンポはタイトル 100／ゲーム中 144／エディタ 78
  - 曲の良し悪しは耳で確かめるしかないが、**壊れると必ず不快になる条件**は
    単体テストで機械的に守る（tests/bgmScale.test.ts）：
    ①全パートの音が C メジャー音階に入る、②和音に 7th を積まない、
    ③ループ内に2種類以上のフレーズが現れる、④ループ長が 25〜120 秒に収まる、
    ⑤ベースが必ずその和音の構成音を鳴らす。
- **効果音は単発のスイープ音で済ませない**（v0.20）。射撃音は
  低音のボディ（発射の重さ）＋ノイズのアタック（火薬の破裂感）＋高音のクリック（立ち上がりの鋭さ）
  の3層で合成する。
- **描画解像度**（v0.20）：論理解像度は 800×544 のままにしつつ、canvas は実際に表示される
  デバイスピクセル数に近い倍率で作り、カメラを同じ倍率でズームして論理座標に戻す。
  こうしないとフルHDで約1.9倍・HiDPI で約3.8倍に引き伸ばされて輪郭がぼやける。
  倍率の上限は性能との折り合いで決める（塗り面積がそのままコストになるため）。

## 12.5 ローカル2P協力 仕様（v0.5・Phase 4 第1弾）

- **モード選択**：タイトル画面で「1人で出撃／2人で出撃」を選ぶ。2人プレイはミッション構成・敵配置とも1人用と同一（MVPでは敵の増員なし）。
- **操作**：
  - 1P＝従来どおり WASD 移動＋マウス照準＋左クリック射撃＋スペース地雷。
  - 2P＝**両対応**。ゲームパッド（Gamepad API＝ブラウザのコントローラ対応機能）接続時は左スティック移動・右スティック照準（傾けた方向へ砲塔即応）・R1/RB 射撃・L1/LB 地雷。未接続時はキーボード分割：矢印キー移動・IJKL で砲塔を8方向へ向ける（押した組み合わせの方向へ砲塔が回転追従）・Enter 射撃・右Shift 地雷。
  - パッドの接続・切断は2Pの生存中でも随時切替可（毎フレーム接続状態を確認）。
- **共有ルール**：残機は2人で共有（初期3のまま）。弾・地雷の上限（5発・2個）は**プレイヤーごと**に独立。
- **ダウンと復帰**：被弾したプレイヤーはそのミッション中は退場（機体消滅）。**両者とも退場した時点で**残機-1・ミッションリセット。片方が生存したままクリアすれば退場側もペナルティなしで次ミッションから復帰。
- **フレンドリーファイア**：§5 のとおり弾・地雷・爆風は発射者・設置者を問わず全戦車に作用する（相方も撃てば倒せてしまう。協力の緊張感として意図的に維持）。
- **敵AIの標的**：セントリー・ローバーとも「生存中のプレイヤーのうち、射線が通る最も近い1体」を狙う。全員に射線が通らなければ最も近い1体を照準だけ追従（跳弾狙撃の判定も同じ標的に対して行う）。
- **識別**：1P＝青系（従来色）、2P＝緑系のオリジナル配色。HUD に P1/P2 の状態（生存/退場）を表示。
- **カメラ**：盤面全体が1画面に収まっているため分割・スクロールなし（現状維持）。
- **実装細部（v0.5.1 暫定解釈・★オーナー確認待ち）**：
  - 2Pの初期位置はステージデータに持たず「P1の隣接床タイル」を自動探索（右→左→下→上→斜め→距離2の順。全ミッションで確保できることをテストで担保）。
  - IJKL照準の砲塔回転速度は540°/s（調整値）。パッドのスティックデッドゾーン（誤入力防止の不感帯）は0.25、射撃・地雷は押下エッジ検出（1押下1発）。
  - パッドの移動は傾き量によらず常時フルスピード（§4の移動速度単一値に合わせる）。

## 12.7 ステージエディタ仕様（v0.8・Phase 4 第4弾）

- **入口**：タイトル画面の「エディタ」ボタン（または E キー）で EditorScene へ。
- **編集**：25×17 グリッドをクリック／ドラッグで塗る。パレットで選択：`.`床／`#`壁／`X`破壊可能壁／`H`穴／`P`自機／`A`〜`D`敵4種。右クリック（またはドラッグ）で床に戻す。**外周1マスは常に `#` 固定で編集不可**。
- **配置ルール**：`P` は常にちょうど1つ（新しく置くと既存の P は床に戻る）。敵は合計12体まで（性能と難易度の上限）。
- **検証**：プレイ開始時にチェックし、問題があれば理由を表示して開始しない：P がある／敵が1体以上／P の隣接に床（2P湧き用）。「開幕時に P から敵へ射線が通る」は**警告表示のみ**（自作ステージの自由度を優先し、開始は許可）。
- **テストプレイ**：エディタから1人/2人を選んで即プレイ（1ミッション構成）。クリア/ゲームオーバー後はエディタへ戻る。**タイム記録（ベスト保存）の対象外**。
- **保存**：localStorage に3スロット（`hanedan.editor.slot.<n>`）。加えて JSON テキストのエクスポート／インポート（テキストのコピペで他ブラウザ・他人と共有可能）。壊れたデータは安全に拒否。
- **UI**（v0.17）：下バーのボタンは省略形にしない（「保1」では初見で意味が取れないため「保存1」等）。
  ボタンは等分割ではなく実際の文字幅で並べ、端のボタンが画面外に切れないようにする。
  **全消去は取り消せないので確認ダイアログを挟む**（誤クリックで編集内容を失わないため）。
- スコープ外：本編ミッションへの組み込み、オンライン共有。

## 15. 公開（Phase 9・v0.19）

- **配信先**：GitHub Pages（`https://bmb9mm64-source.github.io/-/`）。既定ブランチへの push で自動公開する。
  公開前に型チェックと単体テストを通し、落ちたら公開しない。
- **完了の定義**：*誰でも遊べる URL があり、README を読めば何のゲームか分かる状態*。
- **知財の最終確認（2026-08-08 実施）**：公開物に外部由来の資産が無いことを確認した。
  - 追跡ファイルに画像・音源・フォントのバイナリは**1つも無い**（ビジュアルは全てコード描画、音は Web Audio の自作合成）
  - 実行時の外部通信は**無い**（favicon も data: URI、フォントはシステムフォントのみ）
  - 出荷物（`src/` と `index.html`）に原作の固有名称は**含まれない**（原作への言及は GDD と README の
    「何のメカニクスを再現したか」「任天堂は関与していない」を説明する箇所のみ）
  - 依存は Phaser 3 のみ（MIT ライセンス）
- **ライセンス表記（2026-08-08 決定）**：**LICENSE ファイルは置かない**＝既定の「全権利留保」のまま。
  - GitHub 上でコードを読むことはできるが、コピー・改変・再配布は許可していない状態。
  - この向きを選んだのは**取り消せるのはこちらだけ**だから。あとから MIT 等を付けることはいつでもできるが、
    一度 MIT で公開すると、その時点のコードを取得した人の再利用の権利は取り消せない。
  - 再利用可能にしたくなったら、そのときに LICENSE を追加して決め直す。
